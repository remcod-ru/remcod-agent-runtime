# ADR-0002: Канонический версионированный протокол

- Status: Accepted
- Date: 2026-08-30

## Контекст

Публичные Session, Turn, Step и RuntimeEvent пересекают границы пакетов, хранилищ и транспортов. Для них нужны одновременно runtime-валидация, TypeScript-типы и переносимое описание схемы. Особенно опасно расхождение пары `event.type`/`event.data` или незаметное принятие нового события старым reader: такое расхождение меняет восстановленное состояние.

## Решение

Protocol v1 имеет буквальную версию `"1"`, явные конечные автоматы и закрытый discriminated union событий с отдельной data schema для каждого типа. Публичные Zod-схемы являются runtime source of truth; TypeScript-типы выводятся из них, а JSON Schema генерируется из них и проверяется parity-тестами. Неизвестный тип события в v1 отклоняется. Совместимый reader может только явно спроецировать его в `unknown`, не изменяя runtime state.

## Почему

Отвергнуты TypeScript-типы без runtime-схем: они исчезают после компиляции и не защищают внешние данные; цена этого варианта — поздние ошибки и несовместимые записи. Отвергнуты независимо написанные Zod и JSON Schema: две канонические модели неизбежно расходятся, а цена — двойная миграция и ложная совместимость. Отвергнут открытый union событий: он упрощает расширение, но позволяет старому reducer молча построить неверное состояние. Цена выбранного решения — для несовместимого расширения потребуется новая версия протокола и явная стратегия чтения.

## Последствия

Любое новое публичное поле, состояние или событие проходит через Zod-схему, переходы и schema parity. Writers не могут выдавать неизвестные v1-события как совместимые. Consumers получают предсказуемый fail-closed контракт, но обязаны обновиться или явно выбрать unknown projection при появлении новой версии.
